# 条件型被动设计稿 · v0.20

> 依据：《被动效果设计交接说明 · v0.20》（DESIGN_V020_PERK_BRIEF.md）。
> 范围：28 张卡（含首版 20 张标记）、1/2 阶数值、3 张陷阱及原因、6 条打法描述、10 条边界测试，另附实现对照。

## 0. 设计前提（从现有工程核对得出）

写卡前核对了 `arena_hero.gd` 与 `arena_definitions.gd`，有 5 件事会直接影响卡面：

| # | 事实 | 对设计的影响 |
|---|---|---|
| 1 | 三名英雄伤害类型不同：骑士、游侠打物理，法师打法术。敌人分别有 `armour` 和 `resistance`。 | “破甲”如果只看护甲，法师拿到就是废卡。改为 **“高防”= 按英雄自己的伤害类型取护甲或抗性 ≥ 0.4**。卡面写“对高防敌人”，图鉴里解释。 |
| 2 | 护甲 ≥ 0.4 的只有苔甲守卫 0.55、符文重盾傀儡 0.58、负盐寄居蟹 0.58；三个首领护甲都在 0.15–0.30。 | “高防”和“精英/首领”两类卡**目标不重叠**，可以并存，不会互相替代。 |
| 3 | 英雄当前**没有暴击系统**（`crit` 只出现在音效名里）。 | 暴击卡需先补系统。本稿约定：基础暴击率 0%，暴击伤害 ×1.5，暴击时伤害数字放大并换色。 |
| 4 | 上一轮已做成“边移动边普攻”。 | “站定”不再是攻击的前提，而是一个**真正的选择**：站住打拿加成，走位打保命。姿态卡因此成立。 |
| 5 | 现有 `attack_damage_against()` 对满血/处决/精英加成是**连乘**。 | 与交接说明“全部加算”冲突。新系统改为：所有伤害加成先求和、封顶 +80%，再乘一次。 |

另外两条全局约定：

- **英雄共用一个卡池**，不分职业。是否好用由玩家判断（骑士更容易“站定”，游侠更容易“连续移动”），这本身就是构筑的乐趣。
- **“下一击”类效果**不算隐藏计数：它是一个二值状态（蓄势/未蓄势），英雄脚下必须有可见的蓄势光，攻击消耗后立即熄灭。

| 类别 | 数量 | 普通 | 稀有 | 史诗 |
|---|---|---|---|---|
| 敌人状态 | 8 | 4 | 3 | 1 |
| 自身状态 | 7 | 4 | 2 | 1 |

- 稀有度只影响出现频率（普通 60% / 稀有 30% / 史诗 10%），不影响数值上限。
- 陷阱 3 / 28 ≈ 10.7%，略高于“建议 ≤10%”，但符合“陷阱 ≤3”的硬规则；若要严格 ≤10%，首版 20 张里只放 2 张陷阱（见第 7 节）。
- 纯加成卡（无条件、无代价）只有 0 张；条件宽松的卡数值 ≤ +15%。

## 3. 叠加与封顶规则

| 效果 | 单卡上限 | 合计上限 | 计算 |
|---|---|---|---|
| 伤害 | +40%（2 阶 +45% 仅限苛刻条件：处决、背水） | +80% | 所有伤害加成与减益**先相加**，再乘基础伤害 |
| 减伤 | 20% | 40% | 相加；“受到伤害 +X%”视为负减伤 |
| 移速 | ±20% | ±30% | 相加 |
| 攻速 | ±30% | ±40% | 相加 |
| 射程 | ±20% | ±25% | 相加 |
| 暴击率 | +30 | +40 | 百分点相加 |
| 暴击伤害 | +50% | +80% | 在 ×1.5 基础上相加 |
| 穿透 | 25% | 40% | 与学说穿透分开计 |

> 处决 2 阶 +45%、背水 2 阶 +40% 超出“单卡 +40%”时，以 +40% 为准，或者把处决 2 阶改成 +40%。建议首轮先按 +40% 封顶测，再决定是否放宽。

## 6. 玩家怎样“读出条件”（UI 要求）

规则 2 要求条件不查面板就能判断。每类条件对应一个固定的可视位置：

| 条件 | 显示方式 |
|---|---|
| 敌人满血 / 低血 | 持有相关卡时，敌人血条在阈值处多一道刻线（30% / 40% / 50%）；满血敌人血条带细白边 |
| 精英 / 首领 / 高防 | 已有的精英标识；高防敌人在持有“破防”时血条左侧显示小盾 |
| 敌人移动中 | 不额外显示（肉眼可见） |
| 自身低血 / 满血 | 英雄头像血条在阈值处刻线；条件成立时刻线变亮 |
| 士兵距离 | 持有孤狼或并肩时，英雄脚下显示 120 半径淡圈，满足条件时变色 |
| 站定 | 脚下圆环 1.5s 内逐渐合拢，合拢后发光 |
| 蓄势（急流 / 急停） | 武器或脚下出现蓄势光，攻击后熄灭 |
| 生效提示 | 加成生效的那一击，伤害数字换色并在旁边显示卡的小图标（不显示文字） |

## 8. 实现对照（给程序）

| 需求 | 现状 | 改动 |
|---|---|---|
| 加成加算 | `attack_damage_against()` 对满血/处决/精英连乘 | 新增 `perk_damage_bonus(enemy)` 汇总所有条件加成，封顶 0.8 后一次乘入；旧连乘逻辑随旧卡池下线 |
| 精英判定 | 只认 `elite` 与 `kind=="moth"` | 改为 `elite or data.get("boss",false)`，否则星界巨像、沉锚巨蟹不算首领 |
| 高防判定 | 无 | `defence = data.armour if hero 伤害类型==0 else data.resistance`，≥0.4 |
| 暴击 | 无 | 新增 `crit_rate()` / `crit_damage()`；基础 0 / ×1.5；暴击数字放大换色 |
| 站定 / 连续移动 / 急停 | 无 | 在英雄 `_physics_process` 记录 `still_time`、`move_time`、`stop_window`；翻滚清零 `still_time` |
| 蓄势 | 无 | 布尔 `primed`；急流、急停满足即置真，下一次普攻或技能命中前消耗 |
| 士兵距离 | 已有 `game.soldiers` | 每 0.1s 统计 120 内存活士兵数，缓存给孤狼/并肩 |
| 最大生命修改（玻璃） | 已有 `max_health` 重算逻辑（第 129–131 行） | 复用，按比例保留当前血量 |
| 数据 | 旧 40 卡在 `arena_perks.gd` | 新卡单独放 `arena_conditions.gd`（或 JSON），按第 2 节模板字段；旧图鉴先隐藏 |

## 9. 对“仍开放的决策”的建议

| 决策 | 建议 | 理由 |
|---|---|---|
| 池子 20 / 28 / 36 | 首版 20，第二批补到 28 | 20 张已能覆盖 5 套打法；一局 10 次三选一共看到 30 张，20 张池子重复感可控 |
| 是否保留 2 阶 | 保留 | 一局 10 次选择、20 张池子，不保留 2 阶会经常出现“三张都不想要”；升阶也给“围绕一张卡构筑”一个明确的方向 |
| 陷阱占比 | 首版 2 / 20 | 满足 ≤10% 建议 |
| 出战配置 | 本版不做 | 先验证局内三选一是否已形成打法；出战配置等于再加一层系统 |
| 旧 40 卡图鉴 | 隐藏，不删 | 存档与历史数据保留，避免改造成本 |
