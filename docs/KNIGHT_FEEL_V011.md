# v0.11 骑士手感样板

本轮只把骑士做成可比较、可试玩的样板。负责人先否定了沿旧头盔形象生成的方案，随后要求青年、利落卡通。最终接入露面短发、银甲红披风的原创青年剑士。没有将小样写成三英雄美术全部验收。

## 体验入口

外层试玩.bat进入正式游戏，仍从用户原档或正常新档开始。骑士手感实验.bat启动同一个EXE，参数`-- --feel-lab`；实验场在内存中使用永久5级、固定敌人、恢复生命和重置冷却的明确夹具，不持久化。可切原版、1.0/1.3视觉尺寸和减少动态，并重新摆放敌人。左键普攻、WASD/右键移动、Q震地斩、Space战吼。返回正式地图时重新读取正常档。

## 表现与接口

ArenaFeel统一反馈配置。Enemy.take_hit与Game.feedback追加可选攻击类别参数，记录来源、目标、物理/法术、攻击类别及是否击杀；旧调用仍兼容。反馈不重新计算伤害，技能类别不根据英雄当前姿势猜测。

ArenaVisualFeedback只操作精灵比例、材质和播放速度：闪亮60ms，挤压约120ms恢复；震地斩令受击者及已出手的骑士局部停顿约60ms。输入、波次、技能CD和战斗逻辑继续，移动取消后摇会清除停顿。普通攻击无全局顿帧；全局时间倍率不改动。重要事件使用衰减创伤震屏，最大6px、重击间隔至少400ms；减少动态关闭震屏/停顿并降低闪亮与挤压。未启用镜头推近。

骑士动作仍在同一出手帧结算，预备/接触/恢复权重集中在ArenaMotion。三张原始图的姿势分布并非严格等格，运行使用knight_frames.json的实际切片及脚底锚点，避免裁剑、串行和脚底漂移。维护脚本tools/build_knight_regions.py只分析透明轮廓、生成元数据，不改图片；需要Pillow/numpy/OpenCV，正常运行不需要Python。碰撞12px、拦截容量及技能范围不随视觉放大。

同时修复骑士普攻遍历敌人时，前一目标死亡移出列表导致后一目标被跳过的问题：使用本次攻击的目标快照，伤害数值和范围不变。新增低生命多目标同刀击杀回归；此修复会纠正原先漏判的伤害，不将结果差异全部归因于表现。

英雄伤害数字按目标与伤害类型在150ms内合并，相邻数字错开；塔和士兵没有浮动伤害数字。死亡立刻发放原有奖励并释放拦截，死亡精灵独立淡出。战吼保持增益技能，用光效与受益单位的金色提示表达；不新增大招伤害或暴击规则。

真实音效共16个OGG约161KB，具体许可见AUDIO_V011.json。动作、命中分层播放，重要技能和受伤使用独立声部；普通音不抢断重要音。沿用总音量设置，内部使用Combat/Interface总线并限幅。未增加音乐或对外新音量设置。

## 验证与录像

tools/verify.ps1增加v011_feel，覆盖单次出手、视觉与碰撞分离、动画恢复、局部停顿期间CD、来源与数字合并、奖励去重、减少动态和切片数据。tools/verify_window.ps1增加v011_window，覆盖两尺寸实窗、英雄页、实验场开关、技能、暂停及尺寸切换。

tools/record_feel.ps1 -Packed生成有声前后对照，双方使用相同敌人布局与操作脚本，明确永久5级/布局夹具。加-Battle则以正式战斗代码和正常局内资源完成首关前三波，使用合法建塔/升级/移动/施法/提前开波，输出前三波日志；永久5级属于解锁档夹具。公开视频为其中连续30秒实战摘录，不冒充完整通关或真人试玩。MP4保留实际音轨并检测静音和持续削波。
