# 核心切片真人首玩验收清单

本清单用于组织下一次真人试玩，不是已经完成的测试报告。所有项目初始均为“未执行”；执行后记录通过、失败或未执行及原因，不凭自动化结果代填。

规则基于[当前切片](CURRENT_SLICE.md)，操作见[试玩说明](playtest.txt)，自动化覆盖边界见[测试说明](TESTING.md)。若实际表现与文档不符，先记录差异，不自行改平衡或恢复旧系统。

## 记录环境

- 实测日期、测试者、是否首次接触本游戏：待填。
- Git 提交完整哈希（`git rev-parse HEAD`）、本地是否有未提交修改：待填。
- 源码运行或导出包；导出包对应的提交与生成时间：待填。
- Godot 版本、系统、分辨率、窗口模式、系统缩放比例：待填。
- 英雄、三组路线选择、最终波次与核心剩余生命：待填。
- 是否使用调试状态注入：待填；若有，单列为夹具测试，不能记为自然开局或通关。

## 第二轮：对比英雄与观感

三位英雄分别另开新局，测试 Space 与 C 是否触发同一个职业主动。骑士是限时复制当前武器；只有游侠有翻滚；秘术师是清弹结界，不把它当红圈或近战无敌。分别记录实际表现、冷却反馈和不理解的地方。

请测试者用自己的话回答，不先暗示“应该好玩”：

- 哪一次选择让你犹豫继续探索还是立即回防？当时防线、金币和波次是什么状态？
- 塔和英雄各解决了什么问题？有没有一方让你觉得没有用途？
- 换武器前后，攻击节奏、能量和打击反馈有什么可感知的变化？
- 跑动、出手、受击、敌人死亡中，哪一处仍像贴图滑动？附短录屏时间点。
- 哪条提示没看懂、哪个面板挡住了战斗？截图注明分辨率和缩放。

## 把问题变成可开发任务

每个问题单独建 Issue：版本与环境 → 起始状态（英雄、金币、波次、路线）→ 最少复现步骤 → 预期 → 实际 → 截图/日志或录屏时间点。素材避免带入个人信息或商业研究图。

把“操作失效/规则不一致”“文案误导”“主观手感建议”分开写。尚未复现就标为待复现；自动化通过不代表真人觉得好玩，本清单也不证明八种路线组合都已通关或平衡。
